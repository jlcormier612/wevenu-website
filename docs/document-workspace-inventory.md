## 2. Two things found in Step 1 that change what Step 2 can honestly build

**A real gap, not invented scope — Recent and Pinned (§ Section 1/2 of the brief) need somewhere to live.** "Most recently *interacted with*" and "venue-controlled, manual, always visible" both describe state that outlives a page load and must be shared across users at the venue. No existing table tracks either. Two small, additive, workspace-only tables are added in Step 2's migration (`document_workspace_interactions`, `document_workspace_pins`) — they store nothing about any producer's own data, don't touch `canonical_documents` or any producer table, and are pure UI-state for this workspace. Flagged here rather than silently added.

**A real, load-bearing tension — the Client Workspace already has a materially better experience than a generic card would give it.** `couple-documents-section.tsx` isn't a plain list — it does inline contract review + sign CTA, invoice line-item breakdown + "go to Payments" CTA, and a Receipts section derived from paid payments (a fifth "document" concept the original ask didn't name, since a receipt isn't stored anywhere as a document — it's a payment record wearing a document's clothes for the couple's convenience). This is called out explicitly in Step 12 of the implementation report rather than silently building over it — see that document's §Client Workspace note for the resulting scope decision.

## 3. This becomes the Step 2 checklist

Every category in the brief's fixed 12-category list (Contracts / Invoices / Questionnaires / Planning / Floor Plans / Wedding Website / Photos / Vendor Documents / Financial / Communication / Exports / Other) maps to at least one row above except **Wedding Website** and **Communication** and **Exports**, which have no document-shaped artifact today (the published site is a live page, not a file; there's no message-attachment surface distinct from the generic `documents` table; the only "export" is the full-account JSON dump, which isn't a per-document concept) — these three categories exist in the workspace's taxonomy per the brief's fixed list, but will show empty until a future phase gives them something to hold. Stated plainly rather than populated with something that isn't real.
