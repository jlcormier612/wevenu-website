# Document Domain — Producer Readiness Matrix

**Date:** 2026-08-07
**Phase:** 5 (2A) — Canonical Adapter Framework. No producer below is implemented in this phase; this is an assessment of how each would fare against the framework built this phase, run through interface validation only (§11), not an implementation.

Owner resolution is tested against `lib/document-domain/owner-resolver.ts` directly. Reference understanding is tested against `canonical_document_references`, whose `reference_type` column this phase corrected to free text (see `20261214000000_document_domain_adapter_framework.sql`'s header — a real gap this assessment itself surfaced: the original 7-value CHECK enum would have blocked Floor Plans, Timelines, Questionnaires, and AI Drafts from ever creating a reference).

## Summary

**6 of 8 producers are fully ready** (Contracts, Vendor Library Documents, Couple Documents, Floor Plans, Message Attachments, Generated Artifacts) — every owner resolves, every reference type is understood, no architectural change was required to support any of them.

**2 of 8 are partially ready** (Legacy Documents, AI Drafts), both blocked by the exact same thing: **Lead is not a certified owner type**, and this phase's own instruction is explicit — "Do not add a Lead owner... leave that producer unmigrated and document why." This is not weakened here. The blocker is real, it is the same blocker for both producers (not two separate problems), and it requires a product decision (does a Lead-owned document become Relationship-owned on conversion, or does the certified model need a sixth owner type?) that this framework correctly does not make unilaterally.

**One real gap in this phase's own first draft was found and corrected during this assessment**, not before it: `reference_type`'s CHECK enum would have silently blocked 4 of the 8 producers (Floor Plans, Timelines/Generated Artifacts more broadly, Questionnaires, AI Drafts) from ever creating a Reference. Corrected to match the certified architecture's own extensibility principle — not a change to the architecture, a correction to match it.
